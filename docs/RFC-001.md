## 1) Summary (TL;DR)

We will build an NBA bet selector that estimates true win probabilities
and surfaces positive‑EV money‑line bets before tip‑off.

**Decision in one line:** We will estimate NBA win probabilities using
an Elo + logistic stack and identify money lines with positive expected
value so that bettors can consistently find edges.

------------------------------------------------------------------------

## 2) Problem & Context

-   **Problem statement:** Sportsbooks provide money lines with implied
    probabilities that are not always accurate. Bettors lack a
    systematic way to identify value bets.
-   **Who is impacted:** NBA bettors, data analysts, and anyone
    interested in sports modeling.
-   **Why now:** Widespread API access (nba_api, odds APIs) makes this
    feasible.
-   **Prior art:** 538 Elo model, public sports betting EV calculators.

------------------------------------------------------------------------

## 3) Goals / Non‑Goals

-   **Goals:**
    1.  Produce calibrated NBA game‑level win probabilities.
    2.  Compute expected value (EV) for each money line.
    3.  Provide an automated tool that logs and surfaces high‑EV
        opportunities.
-   **Non‑Goals:**
    -   Parlays, player props, and live betting (out of scope for v1).

------------------------------------------------------------------------

## 4) Requirements

-   **Functional:** Ingest NBA schedule, odds, and injuries; compute win
    probabilities; output EV for each team.
-   **Non‑Functional:** Run in \<2 minutes per slate; reproducible
    builds via conda env; storage \<1GB.
-   **Constraints:** Dependent on public APIs; requires calibration to
    prevent over/underestimation.

------------------------------------------------------------------------

## 5) User Stories

-   As a bettor, I want clear EV recommendations with reasoning so I can
    place informed bets.
-   As a developer, I want reproducible data pulls so I can retrain
    models weekly.

------------------------------------------------------------------------

## 6) Proposed Solution

### 6.1 Architecture (overview)

    [CLI / UI] → [Data Collectors] → [Feature Builder] → [Model (Elo + Logistic)] → [EV Calculator] → [Reports]

### 6.2 Components

-   **CLI:** `evfinder` with commands `collect`, `train`, `predict`,
    `report`.
-   **Data Sources:** `nba_api` (games/boxscores), Odds API (money
    lines), NBA injury reports.
-   **Model:** Elo baseline + logistic regression with calibration.
-   **Infra:** Conda env in `environment.yml`; optional Docker.

### 6.3 Alternatives Considered

-   Pure Elo (simple, less accurate).
-   Gradient boosting (higher accuracy, less interpretable).
-   Chosen: Logistic stacked with Elo for balance.

------------------------------------------------------------------------

## 7) Detailed Design

### 7.1 Data Schemas

  -----------------------------------------------------------------------
  Entity                  Key                     Fields
  ----------------------- ----------------------- -----------------------
  games                   game_id                 date, home, away,
                                                  final_home, final_away

  odds                    game_id, ts             ml_home, ml_away, book

  injuries                ts, team, player,       
                          status                  

  features                game_id, ts             elo_diff, rest_diff,
                                                  inj_diff, market_prob

  predictions             game_id, ts             p_home, p_away,
                                                  ev_home, ev_away,
                                                  model_ver
  -----------------------------------------------------------------------

### 7.2 EV Formula

EV(\$1) = `p*b − (1−p)` where: - `p` = estimated win probability - `b` =
decimal payout multiplier (from money line)

### 7.3 Example API (CLI)

    evfinder predict --slate 2025-10-01 --asof T-60

Outputs: `predictions.parquet` with probabilities and EVs.
